<objective>
Turn the loopback tile proxy into the single always-on tile path: bind the persisted random port
behind a per-install secret path segment (D-05, D-06), and replace the coverage-miss 404 with a
302 redirect to the operator's upstream CDN (D-02, D-03, D-04).

Purpose: `tile_proxy_server.dart:158`'s `if (region == null) { 404 }` is the whole design change
(RESEARCH.md 3). A 404 is not a neutral answer — `Reason::NotFound` backs off to
`Duration::max()` and is never retried, and `noContent` is persisted as an empty tile row, so
today's miss handling would turn every uncovered tile into a permanently cached blank one the
moment the online path also routes through the proxy. Redirecting instead keeps MapLibre's own
platform stack fetching online tiles (criterion 6), lets an offline failure surface as
`Reason::Connection` (the one class retried on a connectivity edge), and makes coverage degrade
per tile rather than per screen.

Output: a proxy that serves local tiles when a region covers them, redirects when one does not,
and answers 503 — never 404, never 204 — when it cannot yet name an upstream target.
</objective>

`bool isSafeRedirectTarget(Uri uri)` returns true only when: `uri.hasScheme` and the scheme is

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| co-resident app -> loopback proxy | any process on the device can connect to `127.0.0.1:<port>`; only the secret path segment distinguishes our own MapLibre from an attacker |
| persisted settings -> `Location` header | an operator-supplied (and possibly stale or tampered) template becomes an outbound redirect target |
| proxy -> upstream CDN | one TileJSON fetch crosses out of the app; every tile fetch is delegated to MapLibre's own stack |
| request path -> filesystem | the pre-existing traversal boundary D-07 forbids loosening |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

A wrong or absent secret answers 404 with no body and never reaches region resolution or the filesystem. |
| T-39-10 | Information Disclosure | secret leaking through the base URL | mitigate | `tileProxyBaseUrlProvider`'s doc comment is updated to state the base URL now carries a secret and must not be surfaced in user-visible UI or logs.
