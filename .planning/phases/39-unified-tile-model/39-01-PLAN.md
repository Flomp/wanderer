<objective>
Build the Android `setConnected` pulse (D-12) behind a platform channel, rewrite the now-false
`MainActivity.kt` justification comment (D-14), confirm iOS gets nothing (D-13), and retire the
ROADMAP risk gate on a physical device **before** the phase invests in the style/provider
collapse.

Purpose: ROADMAP success criterion 1 (the recovery case) rests entirely on forcing MapLibre to
retry `Reason::Connection` failures. The app pins `MapLibre.setConnected(true)` permanently, so
the false->true edge that drives `networkIsReachableAgain()` never occurs. It is **untested**
whether a brief `false` window drops in-flight loopback requests. If it does, the documented
fallback is a full `setStyle` reload — and every later plan in this phase needs to know which
mechanism it is wiring.

Output: a `pulseMapLibreConnectivity()` Dart entry point, its Kotlin handler, a rewritten
`MainActivity` comment, an extended on-device harness, and a recorded developer decision on
which recovery mechanism Plan 08 wires.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dart isolate -> Android native | `MethodChannel` messages cross from Flutter into `MainActivity`; process-local, not an IPC surface other apps can post to |
| App process -> MapLibre Native global state | `MapLibre.setConnected` mutates a process-wide gate that governs every online file request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | Elevation of Privilege | `MainActivity` method-channel handler | mitigate | Handler accepts exactly one method name (`pulseConnected`), reads no `call.arguments`, and calls only `MapLibre.setConnected`; every other method returns `result.notImplemented()`. Flutter method channels are process-local — no cross-app IPC surface is created. |
| T-39-02 | Denial of Service | pulse suppressing in-flight requests | mitigate | The two `setConnected` calls run back-to-back on the same main-thread turn, with no delay, so the `false` window spans no `schedule()` opportunity. The blocking checkpoint in this plan exists specifically to prove that on hardware; if it fails, the phase switches to the `setStyle` fallback rather than shipping an unverified pulse. |
| T-39-03 | Tampering | iOS drift into symmetry | mitigate | `pulseMapLibreConnectivity()` returns before touching the channel on non-Android, and its doc comment records D-13's rationale so a later reader does not add an Apple-side counterpart that would introduce a `NetworkStatus::Set(Offline)` path iOS does not have today. |
| T-39-SC | Tampering | npm/pip/cargo/pub installs | accept | This plan adds zero package-manager dependencies (`pubspec.yaml` is not in `files_modified`). No legitimacy audit is required because no install task exists. |
</threat_model>
