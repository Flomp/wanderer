<objective>
Delete `TrailMap.offline` outright, along with both compose branches and both `ref.listen` forks,
and drop the argument at all three call sites (D-16, D-01).

Purpose: this is the defect the phase exists to kill. `TrailMap.offline` *is* reactive — the
detail screen passes `offline: !ref.watch(onlineStatusProvider)` — but the flip cannot reach the
native map: `build()` recomposes the style and assigns it to `_lastStyleJson`, `_buildMap` returns
the cached `_mapOptions` (rebuilt only when `disabled` flips), and `_swapStyle` guards on
`json != _lastStyleJson` which the recompose already satisfied. So even a later theme toggle
cannot rescue it. Removing the parameter removes the branch, and with it the whole bug class —
plus the separate shipped bug where `offline: trail.isOffline` conflated "downloaded" with "no
connectivity".

Runs in parallel with Plan 07, which performs the identical deletion in `NavigationScreen`; the
two files share no edit surface.

Output: a `TrailMap` with one style path and three call sites that no longer pass a mode.
</objective>
