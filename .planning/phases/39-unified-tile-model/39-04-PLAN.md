<objective>
Extend the proxy from tiles to the other two style resources: glyphs and sprites (D-11). Both
serve from `map_cache` when the file is present and reverse-proxy from the operator's upstream
template when it is not, writing the fetched bytes through into the cache.

Purpose: the pre-unification offline style pointed `glyphs`/`sprite` at `file://` unconditionally,
which breaks a first-run-offline user outright — no warm cache means no labels and no icons. The
online style pointed them at the CDN, so the two paths forked for no structural reason
(RESEARCH.md 2). Routing both through the proxy makes the model uniform, and because a style load
issues a handful of glyph/sprite requests rather than tens of tile requests per pan, reverse-
proxying those specific bytes is affordable where reverse-proxying tiles is not (D-02 vs D-11).

Output: two new proxy route families, a sprite filename whitelist in the existing path-safety
module, and write-through caching that retires the map-open cache warm (deleted in Plan 07).
</objective>

`Future<void> _serveCachedAsset(HttpRequest request, {required String localPath, required String? upstreamUrl, required ContentType contentType})`:

  2. Otherwise, if `upstreamUrl` is null or `isSafeRedirectTarget(Uri.parse(upstreamUrl))` is

     template may simply not have been fetched yet and MapLibre must retry (D-04's rule applies

     respond 200 with the bytes. On any failure, delete a partial `.part` if present and answer

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request path -> `map_cache` filesystem | `{fontstack}`, `{range}` and the sprite filename arrive from the request and would otherwise become path segments |
| operator asset host -> `map_cache` | reverse-proxied bytes are written into a cache that later renders as trusted map content |
| co-resident app -> proxy | the secret prefix from Plan 03 gates these routes identically to the tile routes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-15 | Information Disclosure | glyph/sprite path traversal | mitigate | Every path is produced by `glyphCacheFilePath` (4-entry fontstack whitelist + anchored `^\d+-\d+$` range) or `spriteCacheFilePath` (8-entry filename whitelist). Both throw `ArgumentError` before any `p.join`, and the proxy converts that into a 404 without touching the filesystem. No request segment is ever concatenated onto `_cacheRoot` (D-07). |
| T-39-16 | Tampering | cache poisoning through write-through | mitigate | The upstream URL is built only from the persisted `glyphUrl`/`spriteUrl` template and revalidated by `isSafeRedirectTarget` before the fetch; non-200 responses are never written; bytes land in a `.part` file and are atomically renamed, so a truncated download can never be served as a complete asset on the next local-first read. |
| T-39-17 | Denial of Service | upstream fetch storm during a style load | mitigate | `_inFlightAssetFetches` deduplicates by cache path, so N concurrent requests for one range or sprite sheet produce one upstream request; every later request for the same asset is a local file read. |
| T-39-18 | Denial of Service | permanently blank labels/icons | mitigate | A failed or not-yet-resolvable asset answers 503 (`Reason::Server`, retried) rather than 404 (`Reason::NotFound`, `Duration::max()`) or 204 (persisted as an empty row) — the same D-04 rule the tile path follows, asserted by an acceptance criterion. |
| T-39-19 | Repudiation / correctness | thermal regression from reverse-proxying | accept | Confined to glyphs and sprites: a handful of requests per style load, not per pan frame. The tile path is asserted to contain no `HttpClient` or `_serveCachedAsset` call, so ROADMAP criterion 6 is protected structurally rather than by review. |
| T-39-SC | Tampering | npm/pip/cargo/pub installs | accept | This plan adds zero package-manager dependencies (`pubspec.yaml` is not in `files_modified`); the fetch uses `dart:io`'s SDK `HttpClient`. |
</threat_model>
